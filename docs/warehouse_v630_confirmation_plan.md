# v6.30 固定程序的一次新数据确认

本流程仅在v6.30原18项全部完成、原监督器实际回收、完整算术/证书审计通过，
且同一方法六个角色/折满足严格开发门槛后开放。方法按原登记顺序先P后A；
没有完整winner时，任何分配命令在创建目录、环境或随机流前拒绝。

## 固定输入和方法

- 原v6.20完整冻结双Actor；每帧两动作都由其物理掩码后分布采样。
- 固定六个选中程序的拓扑、叶系数、温度和反馈/解释资格；确认不重新判资格或拟合。
- 主比较基线保持对应v6.28搜索起点，读取原v6.29 G128已审计的`reference`。
- v6.30 C0仍是单独的开发机制对照，不能替换主基线。
- 原18项结果、封条、搜索输入、程序、父资产与审计通过SHA共同绑定。

本版本单独实现协议/命令和重放器，以保留已封存旧源码及其收据含义。
覆盖率、完整五动作KL、场景配对bootstrap等算术复用未修改的v6.29定义，并纳入新源码闭包。

## 数据和单次授权

确认集300个新场景，每task100；压力集另72场景、每task24，每场景3条采样轨迹，共216局。
共372个独立场景、516次显式reset。全部场景与动作流先经四历史根目录的元数据、
精确种子与上下文查重；封存参数禁止使用。压力三轨迹的同场景复用显式登记。

源码、输入资产、完整场景表和查重证据固定后，clearance最长24小时。
首次claim前重查历史stat差异；每次RNG/环境构造前重查顺序、有效期、证据及资产SHA，
写入fsync预授权。单次claim在Actor加载前写入，中断保留claim和失败证据，不自动重采或恢复。
采集期间不声称持续扫描历史库。

记录动作前后公开状态、173维特征、五动作物理掩码及NN完整分布/实际动作。
独立审计不创建环境，从公开状态重建特征、NN分布和抽样动作，检查两角色逐帧无动作覆盖，
并从完整episode重算配送、碰撞和真实停机。未完成episode不得记作零停机。

## 原门槛保持

确认和压力分别要求每角色/折F/E覆盖≥45%、预期F≥40%、F/E一致≥95%/97%、
合格区域KL≤0.20、原始非法动作和未证明路径均0；任务质量各要求配送≥5.5、碰撞≤6、停机≤5%。

相对主基线，两角色的解释覆盖和预期反馈共四端点：先完整episode均值，
再同场景平均三折；压力另平均三轨迹。主确认按task分层的场景配对bootstrap 20000次，
四个单侧98.75%下界全部大于0，并保留保守浮点舍入界。压力bootstrap仅作次级报告，
不替代压力绝对门槛。连续帧、三折、压力三轨迹均不当作独立场景。

先输出原始指标，再从审计数组重新评分，全部相等才写最终确认收据。
失败关闭该候选，不改方法或切换方法重用确认集。

## 命令顺序

`scripts/run_warehouse_v630_confirmation.py`：

1. `--allocate --run-id <new-id> --base-start <proposal> --action-start <proposal>`
2. `--prepare --allocation <allocation.json>`
3. `--pipeline --plan <plan.json>`：查重、采集、逐帧审计、固定评分、独立重算结算。

也可逐步调用`--audit-seeds`、`--collect`、`--audit-collection`、`--score`、`--finalize`。
单步不绕过绑定和一次性claim。没有真实winner时禁止分配正式新随机流。
