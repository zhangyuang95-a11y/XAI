# v6.30 现场训练证据池与反事实标签

新原生程序的反馈需要完整的训练证据链，而非只有可评分的数组。
`warehouse_v630_observed_pool.py`接通新准入、新程序读者及重拟合器，并复用原物理重放和完整NN目标算术。

完整源episode绑定有限owner、独立程序证据场景表、行为NN、公开动作前后状态、
实际动作、reward、终止/停机事件和初末完整环境/RNG状态。无新环境构造或reset的物理重放
检查每一步实际由该行为NN采样，任何动作覆盖、部分episode、篡改reward或末态RNG均拒绝。

将同一批已记录状态交给当前NN重新计算完整分布和动作抽样，只是反事实标签。
原实际动作另存、保持不可变；反事实采样不执行、不声称新随机流、不报告为当前NN任务质量。
目标包重算其全部来源、状态、动作差异和资产哈希后才允许建立当前NN证据或重拟合。
实际PPO程序反馈计数仍只能来自真实rollout与实际接受的优化更新。

四类程序证据按完整场景隔离，全部排除在NN梯度缓冲之外。
本模块的scope标记不代替有限owner的历史种子查重、原reset授权和训练池成员检查。
普通调用先核验真实开发与一次新确认准入；未通过时不进入源轨迹或随机数重放。

测试使用从已存合成状态恢复的完整物理轨迹及合成NN，没有新研究场景或真实候选PPO。
正梯度测试是张量兼容验证，不能作为实际候选双角色训练收益或任务质量证据。
当前pilot保持关闭。
