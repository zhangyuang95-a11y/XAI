两角色的合格移动叶都只覆盖 LEFT / RIGHT，没有合格的 UP / DOWN 叶。`whole_tree_path_uncertified_count` 分别为 1,760 / 1,464，表示整树未获路径证明的帧数，只作为诊断；当前准入额外拒绝的是整树原始非法动作数非零，合格区仍严格要求路径证明。

## 覆盖损失来自哪里

树规模分别为 **16 / 14 叶**，最深均为 5；合法性 guard 为 **5 / 5 个**，语义条件为 **10 / 8 个**。这次结果不能用“全部容量都被 guard 消耗”解释。

下表按 **资格集每角色 3,000 个自然帧**做互斥分解：先分已合格区域，再把动作一致率低于 93% 或 KL 高于 0.25 的叶归入“混杂 / KL”；其余检查去掉合法性条件后能否合格。该顺序会把同时缺证明的混杂叶归入混杂类，因此是有明确优先顺序的诊断，不是干预后的因果归因。

| 资格集帧归类 | 角色 1 | 角色 2 |
|---|---:|---:|
| 已合格 | 770（25.67%） | 749（24.97%） |
| 混杂 / KL 不达标 | **2,197（73.23%）** | **2,251（75.03%）** |
| 非合法性质量与支持通过、仅合法性失败 | 33（1.10%） | 0 |
| 仅支持等其他因素失败 | 0 | 0 |

关键叶提供了更直接的证据：

- 角色 1 的 DOWN 叶 8 含 **1,676 帧**（资格集 55.87%），一致率 **48.09%**、KL **0.9972**，且 556 帧原始动作非法。该叶在拟合集已有 3,328 帧，覆盖全部 25 个资格 episode；不能简单解释为没有训练样本。
- 角色 1 的 UP 叶 9（273 帧）与 LEFT 叶 12（129 帧）已经有合法路径，却分别只有 **75.46% / 79.07%** 一致率、KL **0.5656 / 0.5022**。补合法 guard 本身不能解决这些分布混合。
- 角色 1 的 UP 叶 2 有 33 帧，一致率 96.97%、KL 0.1511、经验原始非法数为 0，但缺显式合法路径；这是明确的“质量够、证明不够”局部损失，体量只有 1.10%。
- 角色 2 的 DOWN 叶 7（743 帧）已有合法路径，却只有 **60.43%** 一致率、KL **0.8643**；UP 叶 6（602 帧）与 RIGHT 叶 8（516 帧）也分别只有 **57.48% / 51.16%** 一致率，KL **0.9645 / 0.8422**。

因此，现有搜索选出的较大叶内，完整 NN 的分布仍然混杂，是覆盖损失的主要可观察原因。资格筛选成功留下了一小块高保真区域，但没有把大多数自然帧转成可用解释。支持不足不是本次独立失败类别的主因；这不意味着无限数据或其他搜索一定无帮助，也不证明当前复杂度上限下不存在可行树。

## 整树合法性与 masked 拟合的目标不一致

当前叶分布拟合最小化物理掩码后的交叉熵，并加很小的先验正则。某动作在某帧被掩码排除后，其 raw logit 不参与该帧的动作概率；因此，低 masked KL 本身不保证同一叶在所有掩码下的 **未掩码 raw argmax** 都合法。合格叶的显式路径证明解决了该区域的证据合法性，却没有使未合格叶整体满足 raw 零非法门槛。新的全树门槛正确阻止了发布。

程序仅用于训练反馈和解释，本次从未接管执行动作。整树 raw 非法数并不意味着冻结 NN 经物理掩码执行了非法动作；它说明这个抽取程序不能满足本计划的整体合法性验收。

## 后续设计方向（尚未实施、未验证）

若启动下一候选，应在新的开发设计中把两件事同时作为搜索问题：**保留大区域内 NN 分布的区分能力**，以及**在深度 / 叶预算用尽前，为重拟合后的移动叶分配合法 guard 容量**。叶分布拟合也需要显式处理全树 raw 合法性约束，不能只依赖 masked KL 和最终剔除叶。这样的修改须在新的预先约定开发评估中验证，不能从本验证集挑改动，也不能把坏叶手动改成 WAIT 或添加执行期动作规则。

本次修复和完整 BC 已产生真实指标，但两角色未同时通过程序门槛，不能宣称方法成功，更不能据有限搜索失败断言树容量数学上不可能。当前结果应以原始失败收据、PPO=0 和 pilot 关闭收尾。
