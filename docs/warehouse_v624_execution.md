## 共同起点与对照

历史 S1 六份结果来自已花费的275个 episode；平均解释覆盖36.6764%，最差34.0557%，0/6通过。六份树全部32叶，全部用完4800秒搜索预算。历史成绩只作背景，不作本候选的新独立证据。

P0与P1均从对应角色／折的同一份 S1 拓扑热启动，不称为恢复旧搜索。两组读取相同完整 NN 掩码后五动作分布、拟合帧及场景分区。双方缓存均从相同条件开始，初始重拟合计入新预算。

- P0：保留 S1 候选机制，使用新共同工程基础。
- P1：下游完整分布成本驱动的稀疏节点交替优化、拟合端大混杂叶的两层局部修复、按损失与回收叶预算选择的原子重分配。深度已达6的坏叶定位到可以容纳局部修复的最近祖先，重新拟合该局部子树并按整树评分；不能在没有剩余深度的叶上生成全部被过滤的候选后声称已完成修复。
- 每组每个角色／折最多20,000次新增叶 API，包括初始拟合与最终最多32次重拟合；搜索保留19968次和4800秒，最终阶段保留32次和600秒。
- 程序深度≤6、叶数≤32、每节点最多3个公开源特征。合法性判断及空分支全部计数。
- 12份作业全部完成后才比较。按角色／折平衡P0/P1运行顺序，最多3个作业并发，BLAS等数值库单线程。
- 算法仅使用拟合集。校准用于温度，资格用于确定叶集合，验证用于作业结束后的完整评估。不能用验证结果选择搜索检查点。
- 候选的完整硬路由、叶输出及路径证明重新计算后，按既定拟合评分选择最佳树，永久保留 S1 起点。软成本不替代资格门槛。

每种方法全部六个角色／折须满足：反馈及解释覆盖各≥45%、预期反馈覆盖≥40%、反馈／解释一致率≥95%／97%、合格区域KL≤0.20、原始非法动作及未证明路径均为零。合格方法按最差解释覆盖、最差预期反馈覆盖、最差KL、总叶数排序，完全相同优先P0。无方法通过即关闭候选，不采新数据，不启动PPO。

## 工程验证与预算

共同工程层缓存完整不可变叶统计、复用不变子树路由，数值须与旧实现相同。台账分别记录叶 API、实际凸求解、节点优化、缓存命中、处理行数、耗时和候选来源。

检查点保存beam、最佳树、候选队列及游标、展开集合、缓存及淘汰顺序、round／recipe／停滞状态、随机状态、输入与源码哈希、累计调用和累计耗时。只在已提交的安全边界承诺恢复等价。求解途中硬崩溃保留脏标记与失败收据，不能把未计账重做算作无成本恢复。检查点I/O计入运行预算。

作业异常时调度器终止并等待本次所有子进程，记录进程状态与工程中断，不留下继续计算的兄弟进程，不静默重试。运行中源码改变、模型缺损、哈希变化、台账不一致或审计不完整均阻断推进。

## 后续阶段的固定边界

这些阶段只有先前门槛满足后才能获得各自授权，不能由本阶段计划直接越过。

1. 锁定方法后，新275个episode分为拟合100、校准25、资格75、验证75；50个argmax episode仅用于拟合。另取72个场景×3轨迹的压力集，任务各24个场景。场景与历史及其他分区隔离，先检查种子历史台账。P0和锁定方法在相同新拟合集及预算上重新执行。每个角色的旧S1三棵树作为共同起点池，选择仅用新拟合集，所有起点评估计入预算。
2. 新验证与压力均使用上述严格门槛。按完整场景、任务分层的配对重采样报告提升；压力场景三轨迹同时重采样。两个角色各自的解释覆盖与预期反馈覆盖为四个预登记比较，采用单侧98.75%下界控制整体5%的误判概率。该区间仅描述固定程序跨新场景的差异，不证明多次拟合复现。区间含零不能声称方法优于对照，失败不得在该验证结果上继续调参。
3. 通过后导入原完整NPZ动作权重，先验证Torch、冻结推理、原模型分布和动作一致。新critic、优化器及随机状态单独登记。raw／regularized相同起点、critic、场景和步数；共同使用v6.20参考KL与真实完整episode停机成本。raw外部程序反馈和梯度为零。
4. 先一对20k联合步稳定性校准，再三条新开发继续训练流分别从同一起点启动，200k／300k／400k中选三对都通过的最小预算。前4000步critic-only包含在总预算。程序提取75%／84%／93%，程序反馈λ在80%—85%升到0.01；每epoch重验当前NN，反馈损失按全部物理帧归一。参考KL目标每角色0.01nat、β初值1且仅Actor更新后调整，限制[0.001,100]；参考缓冲初始／当前状态各一半。
5. 逐开发流、逐raw／regularized要求配送≥5.5且≥同场景v6.20的95%，碰撞≤min(6,同场景参考+1)，停机率≤5%；程序开发门槛不降低。不能池化掩盖单流失败。
6. 正式三配对只按质量选择；程序预审不重选。随后一次独立程序审计和每task100新种子留出各只一次。正式质量为配送≥5、碰撞≤8、停机≤10%；程序覆盖≥20%、反馈／解释一致率≥85%／90%、KL≤0.35、原始非法动作零。封存失败／中断关闭候选，下一发布版本递增并使用全新封存种子。
7. Warehouse通过后核验Pong／Kitchen已有收据、资产及执行绑定，不重跑其已使用留出集。逐帧核对演示、真人接管、恢复、回放与反事实的AI动作来自绑定NN与物理掩码；A/B同regularized哈希，C绑定独立raw哈希。三域全部通过才发布。解释只引用合格且与当前NN动作一致的证据。

整个程序抽取对照中NN冻结，没有配送策略变化。旧14.93配送／2.84碰撞／1/75停机只属于历史开发记录；新程序覆盖提升不能写成任务质量或真人协作收益。
