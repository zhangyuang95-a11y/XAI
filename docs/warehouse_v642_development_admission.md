# 真实开发预算锁

`v642_development_admission`接受200k／300k／400k有序尝试，每个预算必须有三个实际完成的流。
每流输入为`completed_assets`、`final_programs`和`quality_gate`的内容哈希指针。
完成训练的实际退出、原生更新、同一起点、源数据隔离及全状态导出由长训练独立资产读者重放。

三个最终程序池均通过时，必须有同一预先封存75场景cohort的三份独立质量审计。
读者实际重跑该审计，逐字段比较原收据；任务整数总量、四程序指标与真实程序梯度计数重新判门。
不得池化掩盖一个流失败。较高预算必须从同流相同Actor／critic／空优化器／随机起点重启。

若某预算的最终程序预检失败，三个流均保留完整最终程序结果，且不能为该组分配质量cohort。
失败程序池单独重放完整NN目标、固定资格和程序指标；缺失的任务成绩记为未评估，不能伪造零分或成功。
程序拟合/训练中断缺少完整证据时拒绝锁预算，不能依据手写`passed:false`跳过低预算。

首个三个流全部实测通过的预算才允许创建唯一只读`budget-lock.json`。
`read_budget_lock`再次独立重放，返回不可直接构造的绑定对象；这只允许后续正式训练准备。
它不授权封存集，不宣称模型已验收，不开放pilot。

当前只有边界软件测试，没有据此签发真实锁或运行长训练、质量场景、程序审计、留出测试。
