# New finite long target storage

This source version applies only to a newly claimed finite long owner. The
current 20k run, recovery, original 407 sources and historical target packages
are unchanged. Scalar NN forwards, recorded action seeds and native target data
schema remain identical. This is a new, explicitly registered storage producer.

It produces canonical twelve NPZ and eight rows JSON inside an exclusive,
unbound stage. Rows are SHA addressed hardlinks. The first future call's NPZ
baselines are permanent immutable inodes; subsequent new logical NPZ are real
APFS clones patched only in differing blocks. Kernel clone failure is fatal.
There is no copying fallback. Final files are byte identical to canonical
numerical output and the native checked_targets reader still replays NN values.

Only newly registered stage scratch NPZ may be consumed, after same-SHA final
publication and before target manifests or seals. Materialization receipts list
them as consumed temporal inputs, with pre-consumption SHA/size and an existing
same-SHA final equivalent. They are not persistent dependencies. CAS baselines,
source snapshots, stage/cleanup/storage ledgers and final files remain read-only.
The independent storage reader rehashes every persistent reference and accepts
no general missing-reference exception.

This storage transformation cannot establish training quality or release
acceptance. Real copied-byte helper probes measured approximately 58.35 MB rows
per call reduced to four shared CAS objects, and 33.22 MB NPZ with 26.93 MB shared
APFS extents. Per-call exclusive NPZ allocation was 7.4–8.4 MB in those two probes;
these are engineering measurements, not a guarantee across unseen targets.
Long-run preparation remains closed until its source contract and available
capacity cover a conservative complete-run budget.

## Full materialization engineering probe and capacity boundary

A two-package copied-byte probe used the already spent native call 0 and call
58 arrays/rows. The probe explicitly replaced the admission gate with a named
synthetic context and returned cached probabilities; it executed zero NN
forwards, environments, training updates or new scientific evaluations. Final
12 NPZ and 8 rows matched each old package's SHA exactly, all old source SHA,
mode and mtime were unchanged, and every persistent dependency remained readable.
The probe is engineering evidence only and cannot grant training admission.

The second package measured 26,929,292 bytes of real shared APFS extents and
8,415,092 bytes of NPZ exclusive allocation upper estimate. Rows reused the
existing CAS inodes. `du` counts APFS shared blocks again, so its 35,561,472-byte
package growth is not physical-exclusive growth; subtracting verified shared
extents gives an approximately 8.63 MB engineering upper estimate including
receipt/metadata growth. These two targets do not bound every future target.

At approximately 640 validations per regularized 200k run, six paired runs
would make approximately 3840 such packages. Target and native provider/event
storage together are already about 49 GB at the measured rates, before the
per-run permanent first baselines, rollout exports, complete checkpoints and
safety margin. The previously measured 48.3 GiB free space therefore does not
establish capacity for all three development plus three formal runs. A single
pair's finite storage budget and remaining disk must be checked before any
actual preparation; long-term retention still needs additional capacity or
separately verified recoverable archiving. No real long seeds were allocated.
