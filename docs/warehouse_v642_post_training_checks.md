# v6.42：20k校准训练的结束检查

程序深12开发及一次新确认已通过；详见 `warehouse_v642_results.md` 与 `warehouse_v642_confirmation_results.md`。
这些结果使用冻结v6.20 NN，不代表新的PPO训练收益。当前配对20k必须另行完成并评估。

`scripts/audit_warehouse_v642_calibration_results.py`只在实际监督器exit0、完整双版本检查点及完成收据一致后导出冻结Actor。
监督器收据必须包含 `exit_code: 0`、`observed_by: "exec_tool_terminal_result"` 和真实 `controller_completed` 内容哈希指针。
不能依据PID消失生成成功收据。

检查包括：相同双Actor与critic初始化、4k前Actor未更新、五个完整检查点、连续更新步数、raw程序损失及梯度为0、
regularized两角色实际正程序梯度及权重变化。实际梯度由逐笔优化收据重算，不从配置或期望值推断。
Actor从检查点张量直接导出，并与原生推理张量逐字节测试；该过程不构造模型、优化器、随机流或环境。

生成的资产明确为不可发布：需要新的独立任务质量评估和最终当前NN的程序评估。
18.6k重新拟合的程序不能自动当作20k NN的审计结果。训练中的完整episode结果也不能代替独立任务质量结果。
质量和程序通过后仍需三个开发流预算锁定、正式配对、一次封存审计/留出及三域绑定核验。

## 历史种子查重的工程改进

新增索引版元数据审计器保留旧扫描范围、所有文件哈希、精确整数、分类、区间和冲突规则。
它只用合并区间和二分查找替代每个整数对所有区间的线性比较；原审计器仍保留。
索引源码哈希额外写入证据，并在完整triage前后复核。
端点/间隙/重叠、实际声明边界、完整小型审计输出、triage及原精确投影的测试均通过。
这项改进尚未接入正在运行的02训练审计；运行中的源码契约保持不变。
