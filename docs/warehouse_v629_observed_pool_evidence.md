# v6.29 真实源轨迹与当前NN反事实重标注的分离

## Material Passport

- Mode: run / validate；Date: 2026-10-21。
- Scope: program evidence provenance and conditional scheduled-refit integration。
- Verification: same-agent synthetic tests plus read-only v6.28 terminal observations；不是正式审计或模型验收。

## 新增来源核对

`backend/training/warehouse_v629_observed_pool.py` 将三件事显式分开：

1. **真实源轨迹**：绑定有限owner和证据专用case inventory、源行为NN、完整初末环境/RNG、
   原始公开轨迹和真实动作。从保存状态重放环境，逐帧重算NN分布/动作、物理结果和原始奖励。
   episode必须完整，四个分区按整场景互斥；缓存保留真实执行动作、源NN分布和输入。
2. **当前NN重标注**：保持源观察/掩码/行身份不变，只重算当前完整NN的五动作分布。
   用原登记随机参数耦合抽样，明确标记为固定状态上的反事实动作，不执行到环境。
   另存原真实动作，记录两种动作的差异，不能覆盖或改称当前NN真实episode。
3. **真实PPO反馈**：独立从实际PPO帧记录被接受的程序梯度/优化更新。
   固定证据状态上的反事实actionable coverage不能替代实际PPO反馈率；本包不估计当前NN任务质量。

新版本证据`warehouse-v629-observed-current-NN-evidence.v2`绑定源审计、当前NN、target package、
epoch及完整资产manifest，并带上述反事实范围说明。旧v1 reader拒绝新格式；新reader从原始数组重算。
它继承现有loss接口，仍仅产生loss targets，不能选择执行动作；NN或epoch变化后仍拒绝旧证据。

定期重拟合包装接口在调用既有75%／84%／93%重拟合前后复核源包与target package，
另外写入`observed-source-binding.json`及完成封条。完整owner必须使用这条来源绑定及相应完成标记，
不能把裸v1 target数组或内部通用refit结果当成全部训练来源证据。

## 完整性和已验证范围

23项测试通过，72.12秒：

- 16个明确构造的合成完整episode、1,920联合帧；源Actor是概率一WAIT的合成NN，非实际v6.20。
- 重标注阶段禁止环境构造/reset/step，源动作保持不变；新软NN的反事实动作确有不同。
- 错误scope、部分episode、手改行为动作、奖励、物理配置、RNG及非布尔终止标签均拒绝。
- 缓存数组、源/owner身份或完整引用manifest变化拒绝；不能漏掉已消费的来源文件。
- 反事实包不能声称已执行轨迹、新reset或新随机性，不能替换真实源动作、少报差异或省略分区/资产。
- 新证据保存/重读保持范围一致并接入两个角色的正程序梯度；没有Adam或候选NN更新。
- 定期重拟合能保留反事实范围和源包绑定；普通真实调用在A/B未通过时先于数据/RNG读取拒绝。

owner声明的scope和成员身份仍不能单独证明历史新鲜性或“从未进入NN梯度”。
未来完整Stage C owner必须绑定真实reset授权/台账、源行为NN的训练状态来源、源case成员身份，
并保证证据专用数据不进入PPO/参考KL等NN梯度缓冲。本模块不发行这些权限。
本轮只新增上述工程测试；没有新的科学候选环境采集、拟合、LP、Actor更新或PPO联合步。
