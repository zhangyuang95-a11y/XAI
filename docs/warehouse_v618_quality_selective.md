# Warehouse v6.18：完整 NN 与独立选择性程序

本文件记录已实施的方法及分阶段证据，不代表模型已经通过准入。
目标候选为 `warehouse-v618-quality-selective-01`，目标 release 仍为
`policylens-three-domain-20261016.v6.0`。封存程序审计、留出集及 pilot
在所有前置门槛通过前保持关闭。v6.14–v6.17 资产与原失败收据只读保留。

## Actor 与训练边界

每个角色有独立的 256 宽完整 NN 主支路和可学习稀疏树支路：

`logits = nn256_logits + tanh(gate) * center(tree_logits)`。

门控最后一层全零初始化。初始 BC/DAgger 阶段冻结零门控，策略严格等于
主 NN；树从完整 NN 的 detached 掩码后分布学习。拟合树在零贡献状态下
暖启后，联合 BC 训练完整 Actor。v6.18 不再使用受保护叶的 0.08 残差
夹紧、margin=3 的树叶强制修正或证书安装引起的前向改变。

树深度最多 5、叶最多 16、每节点最多 3 项已登记公开特征。复合风险位
计入两个公开来源。BC 期间支持集可学习，BC 结束锁定支持索引；PPO 中
24%/48%/72% 只记录诊断，禁止整树重建和额外动作 CE；75% 冻结分裂系数
及阈值。主 NN、门控、叶输出继续正常学习。

raw 与 regularized 从同一双 Actor BC checkpoint 开始，架构、场景区块
和预算相同。两者均使用 PPO、价值/熵项及真实完整 episode 停机事件的
cost critic。raw 的全部程序反馈为零；regularized 仅在每 epoch 重验
当前 NN 后接受合格且与实际 NN 动作一致的外部程序 KL。λ=0.01，80%–85%
渐增。正式 self-play 中没有教师动作、伪标签 CE、手写避让或救场动作。

## 独立程序

方法 ID：`independent_selective_masked_distribution_v4`。

程序从完整冻结 NN 掩码后的五动作分布拟合，独立于 Actor 内部树，不覆盖
Actor 参数。三组固定初始化/搜索预算使用 fit episode；搜索计入合法性
守卫的深度、叶与空 fallback 成本，不预设风险/近远根节点。

程序使用 50/25/25/24 个互不重叠 episode 拟合、校准、判定叶资格、验证。
资格及验证使用自然采样轨迹，全部物理帧纳入分母，包括重复碰撞与等待。
每个移动叶必须有对应显式 `legal_ACTION` 路径证明；叶分布重新拟合后，
针对新的首选动作重新证明。无合格叶时仍可拟合程序，向 NN 的反馈保持零。

分别报告合格叶覆盖、解释可用覆盖、反馈可用覆盖、实际训练反馈比例、
过滤前动作一致率、masked KL、非法原始程序动作、两角色程序梯度。
解释必须匹配实际采样 NN 动作；反馈还要求该动作等于当帧 NN argmax。
程序不直接选择任何执行动作。

开发诊断后修正了候选排序：按子分区相对父分区的增益比较，防止已有高分的
WAIT 区域占用搜索预算。空合法性分支只允许为支持和保真已达标、但缺少路径
证明的当前移动动作补证；保留停长候选，合格叶继续分裂必须确有覆盖或分布
收益。搜索预算和复杂度上限保持不变。

新方法另行记录全部帧、物理掩码前的 `whole_tree_raw_illegal_count`，BC、
在线验真和准入均要求该计数为零；缺失字段不能通过。原有合格区域的非法
动作和路径证明统计保留。全树未证明路径数单列诊断，不将其混同为已经发生
的非法动作。旧版本收据保持原口径和原文件哈希。

## 阶段与门槛

1. 不可发布的短工程链路：BC→两臂 PPO→资产加载→授权开发评估→物理回放→
   四分程序拟合/独立审计→completed checkpoint 恢复。
2. 同场景/同动作随机流的旧 NN 对照，及固定质量可靠 NN 的程序可行性诊断。
3. 新候选 BC。程序叶覆盖各≥35%、预计反馈可用覆盖各≥30%；同时记录
   24 局 BC 质量。即使程序失败，也记录预先声明的质量筛查结果。
4. 三个开发配对均通过后，锁定 200k/300k/400k 中最小预算。
5. 正式 6101–6103，仅质量选择，依次程序预审、一次性独立审计及留出。

开发质量：两版本配送≥5.5、碰撞≤6、停机 episode≤5%。程序合格叶与实际
动作可用覆盖各≥30%，反馈/解释一致率≥93%/95%，KL≤0.25，非法动作零。
正式门槛保持原值：配送≥5、碰撞≤8、停机≤10%；程序覆盖各≥20%、
一致率≥85%/90%、KL≤0.35、非法动作零。

新开发配对为 6150–6152，checkpoint 264100–264123，压力 base
264200–264455（三 task×三动作流，共 2304 轨迹/模型），程序审计
264500–264523。原 263xxx 场景仅用于明确标注的已用开发场景诊断。
正式质量/程序预审及封存种子不用于方法调整。

不同预算必须按各自时间窗口从同一 BC 起点训练，不能把 200k 配方续跑
到 300k 后冒充 300k 配方。raw/reg 采用相同的晚期检查点可选窗口；程序
指标和梯度量不能参与质量排名。最终检查点的反馈与准入条件另行验证。

## 执行与发布

独立评估必须绑定源码闭包、冻结资产及双角色哈希，并核对真实 reset 清单。
开发授权拒绝封存场景；审计/留出仅接受现有一次性 claim，执行批次先写入
不可覆盖的使用记录。普通训练调用与 pilot 不因此开放。

发布前逐帧核验演示、真人接管、恢复、回放与反事实中的动作来自绑定冻结
NN 和物理合法掩码，A/B 同 regularized 哈希、C 独立 raw 哈希，资产缺失或
不符拒绝执行。Pong/Kitchen 核验原收据及迁移后执行，不重跑已用留出集。

失败即保存收据并停止该候选，不降低阈值，不使用手写控制器补动作。
