# v6.30 当前NN反馈provider与失败锁存

新provider衔接原生程序、观测证据池与PPO核心。每次反馈导出并验证当前完整双Actor，
按新优化epoch重算NN目标与资格。任一角色严格验证失败，两角色外部程序反馈都锁存关闭；
NN分数恢复不自行开放，仅下一次75%/84%/93%登记重拟合通过才可恢复。

每次安装与验证都保存不可变事件链，绑定owner、源轨迹、重拟合程序、当前NN、完整报告和数据资产。
程序不可在内存中静默替换；重复epoch、遗漏重拟合、缺失或篡改事件均拒绝。
恢复必须保持完整TrainingState、当前NN、owner、所有事件和失败状态；
旧快照后已发生额外工作时，不允许回退旧快照重算该前缀。

raw不构造该provider。regularized的实际接受更新和正梯度计数由PPO核心记录，
provider的资格行数或诊断梯度不冒充接受更新。
所有组件仍不替NN选择环境动作。原v6.29源保持不变。

测试使用合成NN和从存档合成状态重放的完整物理episode。除失效/恢复/篡改拒绝，
还将新provider接入原实际Adam/PPO核心，检查四次合成更新中两个角色均收到正程序梯度。
这些合成更新不是候选训练收据，也不是新Warehouse任务效果或独立确认。

实际候选的完整开发与新数据确认未通过时，构造provider在导出NN或创建目录前拒绝。
有限训练owner、真实reset查重、案例成员/隔离、完整运行检查点及正式准入仍需后续完成。
当前不开放pilot。
