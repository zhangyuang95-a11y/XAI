## 研究流程和安全边界

新包是 `study_vnext`，协议为 `study-protocol-20261029.v1`，协议 SHA 为
`ee583c93308e07dde06cb4fff5d496aa1079a33ac8e0f2fc4919c0c1d982379a`。
操作入口和启动说明见 [README](../study_vnext/README.md)。它使用新数据库与新端点，不自动采用旧参与者数据库。

- 研究者预览可以指定 A/B/C；正式参与者不能选组、模型或场景。当前服务根本不接受 pilot 模式。
- 演示确认要求先有中立按键练习记录、真实绑定演示和匹配帧数/哈希的播放记录。记录只能证明客户端报告了完成，不能证明注意力。
- 问答的坐标是已提交动作；默认选择最近已执行动作。Task 1 的历史可以在当前 Task 2 中询问。未执行决定保持服务端私有。
- 反事实只在隔离副本执行，使用原绑定 NN，不能越过已保存历史范围。它不影响真实游戏；显示的一步分数差独立重算。
- 语言服务只能选择已验证的事实 ID；最终文字由受约束渲染器生成。证据不足必须说明无法推断动机，不能宣称规则证明了唯一因果理由。
- 外发授权与普通记录同意分开、逐报名不可变保存。未另行同意的实例只用本地模板，即使服务全局配置了外部提供方。
- 当前实际模式为本地模板；没有发起真实外部语言请求，没有把已携带的开发程序审计改写为正式独立审计。
- 所有回答访问在 Task 3 撤销，迟到回答也会重验权限。刷新可恢复已有回答，不因回答服务暂时故障丢掉有效会话。
- 规则理解题每域四题，三组相同，Task 3 结束后才开放，答案键不下发。这是待试测的“公开规则/控制理解”工具，不能称为已验证的 NN 策略理解量表。
- 分开记录操作、显式阅读回答模式、输入问题、回放和问答请求等待时间。这些是界面使用时长代理，不是注意力测量；等待包含网络和服务时间。

实现了参与者级数据提取、重复/绑定检查、缺失结果清单、A–B 的 Task 1 调整、A–C/B–C 不调整模型已影响的 Task 1，以及 HC3 区间和三域 Holm 校正。Pong 使用固定初始接触容量作为分母，不能拿原生得分的其他分母替代。

## 已执行的软件验证

- 合成三域×三组完整流程覆盖了绑定、三个任务、恢复、问卷、历史问题与撤销；不计入真人样本。
- 本地真实 PostgreSQL 17.11 演练：9 实例、27 完整任务、81 帧、54 个动作，关闭并重新打开、备份到全新数据库后导出完全一致。
- 并发重复动作只提交一次；另一个事务报告序列化冲突后，可以显式使用原 command ID 恢复。后台没有自动重试。
