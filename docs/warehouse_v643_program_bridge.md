# v6.43 candidate-bound program component

This is program-only infrastructure, not an executable scientific owner or a
passing model receipt. It starts no training, makes no fresh environment reset
or random NN initialization, allocates no seeds, and changes no old assets, claims, numerical kernels or
pilot gates. The v6.42 failed calibration remains failed.

`v643_program_namespace.py` checks a new candidate owner/claim graph under
`output/warehouse_v643/warehouse-v643-risk-calibration-01`. It refuses old owner,
claim, partition, inventory and plan schemas. The graph binds immutable source
files, the original v6.20 reference, both program templates and three finite
inventories. Program evidence uses new candidate-prefixed episode IDs and
900/150/300/300 fit/calibration/qualification/validation episodes, with whole
scene, action-stream and identity separation from NN-gradient and quality data.
Reading a correctly typed graph does **not** recompute full seed-history
clearance or grant reset/optimizer/recovery authority. The finite owner must
verify these independently immediately before execution.

`audit_observed_pool(namespace, source_ref)` replays already recorded complete
physical episodes and their NN actions from saved private environment/RNG
states. It never resets an environment or relabels an incomplete episode as a
negative failure. An in-memory replay seal is not serialized as authority;
restoration must replay original source traces again. It remains the owner's
responsibility to bind original reset journals and ensure that these program
observations never enter NN gradient buffers.

`v643_program_provider.py` retains the v6.42 `Program`, `complete_program`,
legality proofs, fixed topology/support/protected descendants, strict
`current_report` gate, independent forward and budget ledger. The program's
numerical schema is unchanged; the new candidate binding wraps the asset.
`refit_pair_at_boundary` uses the original 75%/84%/93% schedule and records a
new, once-only refit claim per variant/boundary. Qualification is recomputed
from new targets and disjoint qualification data, never inherited from the
template's old passing regions.

`CurrentNNEvidenceProvider(namespace, output=...)` only accepts regularized.
It exports the actual current complete NN with new candidate, variant, pair
and reference metadata, and independently checks both role hashes. Each new
optimizer epoch recomputes full masked distributions on the recorded states,
replays deterministic action draws from recorded RNG identities, recomputes
qualification and independent validation, and emits detached loss targets.
Those relabeled draws are counterfactual numerical evidence, not executed
current-policy outcomes or a new task-quality measurement. Every Actor change
or epoch change expires old evidence. A fidelity failure latches feedback off;
only the next scheduled completed refit can reopen it. No program returns an
environment execution action.

The inherited PPO/feedback kernel keeps raw external program loss, selected
frames and gradients strictly zero without inspecting a provider. The new
provider itself refuses raw construction and restore. Gradient diagnostics
remain separate from accepted optimizer-update counts owned by the future
finite PPO owner.

Provider snapshots bind exact full TrainingState, event chain, source closure,
observed source and failure latch. Restore requires an already fully restored
TrainingState and rejects later or incomplete provider work. It grants no
scientific resume authority. A complete finite collector, current-history seed
clearance, actual reset journal binding, owner integration and explicit
recovery/admission remain required before any v6.43 scientific training.

Engineering tests use temporary synthetic NN tensors and synthetic owner
graphs only. They do not create the real global claim or new scientific
episodes. Their target distributions and gradient computations are actual
numerical calls; their positive software results are not a Warehouse delivery,
shutdown, coverage or independent audit result.
