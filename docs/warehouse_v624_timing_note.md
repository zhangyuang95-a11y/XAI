# v6.24 结果报告的计时表述更正

[完整执行结果与指标](warehouse_v624_results.md)已经随工程中断证据封存，保留原文件字节及SHA。最终只读复核发现其中一处计时表述需要收窄：

“叶求解已在候选评价内”应为“**候选评价期间的叶求解已包含在相应候选评价计时内**”。初始化和候选提议阶段也可能调用叶拟合，应分别计入其实际阶段；不能把所有叶拟合时间都归入候选评价。例如，首折R1/P1的initial和proposal阶段分别有31次叶API调用。

因此，候选评价、节点拟合和检查点bulk的计时可以作为互斥子区间相加，但不构成完整运行时间的穷尽分区。不能遗漏初始化和提议等其他阶段，也不能再次叠加已包含的内部求解时间。

这项更正不改变任何指标、时间数值、7／1／2／2作业分类或`closed_engineering_interruption`终态。当前没有完整12项比较，未选择方法、未进入PPO，pilot保持关闭。勘误单独绑定在紧凑Git证据中，不改写原始清单或冻结源码。
