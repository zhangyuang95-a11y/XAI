# 三领域研究数据保存与导出

核实日期：2026-09-20。生产站点：<https://policylens-warehouse-study.onrender.com/>。

## 已有数据库与保存方式

生产网站已连接 **Neon PostgreSQL 17.11**，不是浏览器缓存，也不是 Render 容器内的临时数据库。v3.7 延用同一个数据库；没有新建服务或购买数据库。现有记录的完整性通过只读查询核实，线上功能验收另使用明确标记为 `test` 的自有身份，不修改既有参与者记录。

每个成功提交的操作在同一个数据库事务里保存人类动作、AI 决策、前后状态、得分和新的进度。事务提交后，页面才收到成功响应。刷新、Render 服务重启和重新部署不依赖浏览器来保留这些记录。未完成的任务同样逐步保存。

问题通过权限检查后先保存原问题与 `pending` 状态，然后请求问答服务，最后保存回答或失败状态。页面只显示最新回答，不会删除数据库中的历史回答。问卷提交成功后保存在同一数据库。

## 数据字典

所有表名使用 `pl3_` 前缀。旧版其他研究表仍留在数据库中，不会被新版本删除或覆写。

| 表 | 主键与关联 | 保存内容 |
| --- | --- | --- |
| `pl3_participants` | `id` | 匿名编号、最初分组、创建时间；仅数据库内保存恢复码的哈希，不保存恢复码明文。分析分组应以实例上的 `group_code` 为准。 |
| `pl3_sessions` | `token_hash` → `participant_id` | 会话令牌的哈希、参与者关联和会话创建时间。令牌不进入研究导出。 |
| `pl3_instances` | `id` → `participant_id` | `domain`、`release_id`、实际 `group_code`、`mode`、演示/Task/问卷阶段、`revision`、当前运行、演示进度、当前语言、场景种子、创建与完成时间。 |
| `pl3_enrollments` | `instance_id` | 同意标记、初始语言、分组来源、场景版本、同意记录创建时间。分组来源区分参与者自行选择、平衡分配和研究者覆盖。 |
| `pl3_runs` | `id` → `instance_id`；每实例每 Task 唯一 | Task 编号、场景种子、最新完整状态、运行状态、得分分项、开始/结束时间。未完成任务的 `ended` 为空。 |
| `pl3_frames` | `(run_id, turn)` | 每一回合的完整内部状态 `state_json`、实际公开状态 `public_json`、AI 决策 `decision_json`、人类动作 `human_action`、保存时间。内部状态包括领域物品、位置、电量、阶段、事件和计分所需事实。 |
| `pl3_questions` | `id` → `instance_id` | 原问题、语言、授权任务 `authorized_run`、被问的历史任务 `target_run` 与帧 `target_turn`、完整结果和证据审计、状态、请求/完成/展示时间。结果状态包括 `pending`、`answered`、`clarification`、`unavailable`、`revoked`。 |
| `pl3_questionnaires` | `instance_id` | 评分、可选文字反馈、理解题字段（当前版本为空）、提交时间。每领域实例只能成功提交一份问卷。 |
| `pl3_commands` | `(session_hash, command_id)` | 请求指纹、命令身份、保存时间，用于重复请求去重。这里不保存请求正文；动作正文已在帧中保存。 |
| `pl3_timings` | `id` → `instance_id` | Task、`active` / `reading` / `replay` / `explanation_wait` 类型、秒数、记录时间。 |
| `pl3_releases` | `id` | 发布清单，包括代码提交、源文件哈希、领域与场景版本、说明权限和发布配置。 |

时间戳为 Unix 秒，可含小数，生产列使用 PostgreSQL `double precision`。时间点应先转换时区再作展示，时长不受时区影响。

### 帧与动作的对应方式

`turn = t` 的 `state_json` 是第 t 次联合动作完成后的状态，也是下一次动作前的状态。若本帧 `human_action` 非空，它与本帧 `decision_json` 一起产生 `turn = t + 1` 的状态。因此，重建“刚刚完成的第 n 回合动作”需要连接帧 `n - 1` 的动作与帧 `n` 的结果。最新一帧的 `human_action = null` 是正常情况，不能解释为丢失动作。

问答的 `target_turn` 保留用户当时看到/选择的回合。v3.6 起为“本步为什么这样做”另存实际已执行动作的证据帧信息，v3.7 继续保持这种对应关系；不能把结果页上的回合号直接当作决策前状态序号。具体绑定应读取该问答的 `result_json.audit`，不要根据自然语言猜测。

### 版本、分组与数据隔离

分析至少按 `release_id`、`domain`、`mode`、实例 `group_code` 和场景版本筛选。v3.6 修改了 Kitchen 规则，v3.7 修改了 Pong 控制器；旧玩法实例保留原始版本记录，不能套用新版规则继续计算。当前参与从新版演示开始。自行选择 A/B 的记录不是随机分组实验。

数据库中保留预览、测试、未完成、失败问答以及被撤权的回答，可用于审计；这些记录不应全部当成有效真人研究样本。分数的 50% 提升仍是需要真人研究验证的目标。

## 获取数据

研究者导出接口已经存在，要求请求头 `Authorization: Bearer <研究者密钥>`：

- 完整研究数据：`GET /api/study/admin/export?format=jsonl`
- 当前发布的真人预实验模式：`GET /api/study/admin/export?format=jsonl&release_id=policylens-three-domain-20260920.v3.7&mode=pilot`。导出旧版本时使用其原始 `release_id`。
- CSV 容器格式：将 `format=jsonl` 改为 `format=csv`。

JSONL 每行是 `{"table":"frames","record":{...}}` 这样的一个记录；CSV 为 `table,record_json` 两列，嵌套状态保留为 JSON，避免丢失领域字段。导出涵盖上表除会话和内部命令收据外的九类研究表，并去掉参与者恢复码哈希。原始问题和反馈可能含用户主动输入的个人信息，因此完整导出仍须作为研究数据保管，不应上传公开仓库。

不要把密钥放在 URL、网页聊天或公开脚本中。由已有私密运行配置或受保护环境变量传给请求头即可。普通参与者无法调用该接口；未经认证返回 403。导出使用一个一致的只读快照、分批读取；先完成临时导出文件再向客户端下载，避免慢速下载一直占用数据库事务。

旧版其他研究表不包含在 `pl3_` 导出中，但仍在现有数据库。需要整库恢复备份时使用数据库管理端/独立备份流程；当前逐行哈希基线是核对记录是否缺失或变化的证据，并非可恢复备份。此次未核实供应商的自动备份保留策略，不能承诺任何特定保留期限。

## 去重、恢复与已知边界

- 同一会话重复提交相同 `command_id`，不会再次行动；同一身份配不同正文返回冲突。`revision` 和 `turn` 同时防止过时页面继续写入。问题用 `question_id` 去重。数据库事务不在不确定提交后自动重放。
- 问答在 Task 2 结束后立即撤权，结果仍保存为审计记录；不会再向参与者显示。如果服务在请求中途重启，已保存的问题可能保持 `pending`，后续请求会把过期请求标为不可用。
- 成功收到服务器确认的动作、问答和问卷已经持久保存；没有提交的输入草稿、尚未到达服务器的按键、格式/权限检查之前拒绝的请求不属于已保存研究记录。
- 活跃、阅读和回看计时是前端采样估计，并随后续操作提交。用户直接关闭页面或网络失败时，尚未提交的尾段可能丢失；不能声称这些分段计时是完整的精确注视时间。服务器任务开始/结束与每帧时间仍独立保存。
- 保存并不等于已经设置好永久备份：数据库服务持续可用、配额和账户管理仍需研究者维护。

本次本地数据库/导出回归为 **28 项通过**。SQLite 测试覆盖事务与重启，PostgreSQL适配器测试包含测试替身，不能将其表述为所有生产故障情境均已实际测试。生产连接与现有记录的完整性另由真实只读检查核实。
