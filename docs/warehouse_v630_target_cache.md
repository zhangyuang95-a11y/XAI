# v6.30 训练目标包的完整重放复用

本改动只作用于尚未注册实际训练的训练证据模块；不修改正在运行的v6.29/v6.30科学源码、预算或判定标准。

一个ObservedPool最多驻留一个目标包的内存证书。首次读取仍完整执行两角色、四分区的原始逐帧冻结NN重放、采样动作重放、来源状态及资产校验；只有成功后才能签发该内部证书。
后续同包读取检查全部目标数组、行来源、包内容、角色哈希、观察审计、源码以及所有绑定文件的SHA。变化即拒绝，不自动重新验证后掩盖篡改。
不同目标包必须重新完整重放并替换旧项；恢复后的pool没有内存证书。没有序列化证书加载接口，也没有训练或数据采集授权。

程序资格与优化器epoch不缓存。每次建立反馈证据，仍对当前程序重新计算资格和严格开发门槛，并生成绑定当前epoch的新封套。旧epoch或旧NN角色哈希仍被拒绝；当前NN导出改变时，新的目标包必经完整重放。
epoch改变且NN/数据未变时，可复用数值目标，但不能复用旧epoch反馈资格。此区别细化了先前开销诊断中的失效描述。

测试比较缓存路径和原完整重放路径的整个证据payload，包括资产引用顺序、重复引用、逐叶资格和所有数值；不采用近似批量NN前向、不改变分母、不缩小资格/验证数据。
测试还覆盖首次8个角色/分区重放调用、后续零额外NN重放、资产/内存篡改、不同包淘汰、恢复后重新验证以及epoch/NN哈希失效。

这些是合成已记录状态的工程验证，不是新候选的覆盖率、真实配对PPO或任务效果。完整训练用时与检查点开销门槛仍需实际测量；不从减少调用次数直接声称四倍训练加速。
