# Cooperative Pong

这是 XAI 项目中的第二个 domain，与 Warehouse 共存。当前版本是一局连续运行的格子像素五球合作接球游戏：三个小球 `A1`、`A2`、`A3`，两个需要双方配合的大球 `B1`、`B2`。小球占 1×1 格，大球占 2×2 格，球拍占 1×4 格；五个球从开局同时存在，碰到边界后反弹并继续留在场内。场地为 30×18 格，物理和画面使用同一套格子坐标；小球和球拍的像素图形缩进所属格内部，不会压住网格线。球拍位于第15行，下面保留两整格空间。

Task 1 进行时，A 组在场地下方看到稳定的“当前意图”气泡：机器人2正在接哪个球、球的类型、距离和是否需要队友配合。气泡的文字只在目标或意图改变时更新，旁边的距离格数仍按当前独立计算刷新；B 组不显示气泡。Task 1 结束后，A 组先从关键事件列表进入回放，也可以拖动时间轴、逐帧查看并提问；B 组跳过回放直接进入 Task 2。Task 2 两组都不能读取 Task 1 解释。

## 本地运行

在项目根目录执行：

```bash
python3 -m domains.pong.web.server --port 8765
```

打开 <http://127.0.0.1:8765/pong>。服务需要保持运行；如果终端进程结束，浏览器会显示无法访问。

操作方式：按住左右方向键或 A/D 移动，松开后停止；浏览器失焦会暂停物理。也可以用页面上的暂停按钮。两块球拍可以交叉或重叠。

## 游戏规则

- A1、A2、A3 是小球，任意一块球拍接住即可。
- B1、B2 是大球，各有底边左右两个接触点，必须由两块不同的球拍在同一接球时刻分别覆盖。
- 球碰左右墙、上边界和下边界都会反弹并继续运动。小球漏接计为 1 次；合作大球漏接计为 3 次，因为它要求双方同时覆盖两个接触点。
- 球不会因为漏接消失，也不会重新生成或换编号。
- 后端与前端共享球的整数左上格、宽高和球拍左端格；显示边框不会扩大碰撞范围。小球只检查它的一个接触格；大球检查底部左右两个橙色接触格。
- 用户计分只看漏接次数。统计同时记录已结算的接球机会、总漏接率、小球漏接率和大球漏接率。
- 当前默认有效时长为90秒，逻辑固定为20Hz；球以每秒2.5格的速度移动。后端只用整数格判定物理，前端按每个20Hz微步在相邻权威格之间插值显示，因此不必等待一次完整格移动才看到画面变化。所有尺寸、速度和时长都在 `configs/default.json` 中配置。

## A/B流程和回放

每个Task只有一局：

1. 两组进行相同练习；每个 Task 只有一局。
2. Task 1 连续运行一局，A 组显示稳定意图气泡，B 组不显示。
3. A 组在 Task 1 结束后先看关键事件，再播放、暂停、拖动、前后逐帧查看，并选择 A1、A2、A3、B1、B2 提问。
4. B 组跳过回放，直接进入 Task 2。
5. Task 2 使用新的 seed 运行一局，双方都没有气泡、解释和问答。

问题绑定 `run_id`、Task、帧号、游戏时间和可选球号。选中的帧同时明确区分“从该帧出发的决策”和“到达该帧的结果”，不会用相邻帧静默替代。回放与问答只读取已保存轨迹，不重新运行控制器，也不修改真实分数或下一局状态。

启动页可以选择：

- `coordination_explanation`：默认协议，A组获得Task 1局后解释。
- `rule_discovery`：探索协议，记录规则学习与协作的整体结果。

协议、组别和 `manual_self_select` 分配来源会写入会话记录，不能混合分析。

## 文件说明

| 文件 | 作用 | 是否可直接运行 |
| --- | --- | --- |
| `config.py` | 五球物理、时间步和实验协议配置 | 否，被环境读取 |
| `configs/default.json` | 默认格子玩法参数；修改后重启服务生效 | 否，配置文件 |
| `environment/model.py` | 球、帧、转移和稳定编号的数据结构 | 否 |
| `environment/engine.py` | 唯一的格子连续物理、反弹、接球机会和漏接计分实现 | 否 |
| `policies/rule_demo.py` | 可核验的规则演示控制器 | 否，被会话调用 |
| `explanation/evidence.py` | 意图气泡使用的自然语言、局后帧证据、回放解释和问答 | 否 |
| `study.py` | A/B权限、意图气泡、Task切换、关键事件、轨迹和问题绑定 | 否 |
| `adapters/core_adapter.py` | 五球公开特征和 `left/right/stay` 动作接口 | 否 |
| `web/server.py` | 连续运行、多会话本地HTTP服务 | 是，用上面的命令 |
| `web/index.html`、`app.js`、`styles.css` | 游戏和局后回放界面 | 否，由服务提供 |
| `training/README.md` | 未来Pong NN训练边界 | 否，当前没有训练入口 |
| `tests/test_pong_domain.py` | 固定物理、计分、权限和快照测试 | 否，用pytest运行 |

## 测试

```bash
pytest -q tests/test_pong_domain.py
python3 -m py_compile domains/pong/config.py domains/pong/study.py domains/pong/environment/engine.py domains/pong/web/server.py
```

当前使用 `rule_demo`，没有合格的Pong NN，不加载Warehouse Actor，也没有启动正式训练。配置写成 `control_mode: frozen_nn` 时会明确报错，不会把规则控制器冒充成NN。

Pong与Warehouse在同一个Git分支中，但当前Render启动入口仍是Warehouse。正式合并到线上服务前，需要在Warehouse服务中显式挂载 `/pong/`、`/pong/assets/...` 和 `/pong/api/...`，并重新完成多会话和A/B权限验收。本阶段未部署、未推送、未声称A组一定优于B组。
