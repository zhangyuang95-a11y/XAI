# v6.42：用户授权的深9／深12配对容量对照

2026-10-22，运行前登记。用户明确授权“允许增加深12对照”。v6.41深9原型已测试但未启动。以同一套v6.40六个最终程序为来源，两个容量臂分别运行2角色×3折，共12项；不按角色混选容量臂。

## 不变条件和独立版本

冻结同一v6.20完整双Actor；保留全部历史深9资产、源码和收据。两个臂均最多256叶，每节点／叶最多3公开源、叶最多20系数。新程序资产逐个显式声明maximum_depth=9或12，使用v6.42读者。历史读者继续拒绝深12，绝不修改全局旧深9常量。

新语法单独验证整树深度、总叶数、公共特征数量；沿用逐路径精确有理数证书计算，声明深度写入资格报告与物理证据。新独立前向按资产深度路由；深12的全部路径重新校验，不把旧深9验证结果当作新树证书。

## 同数据、同算法、同调用上限

冻结原v626核心＋来源程序在旧fit-only风险/选择数据上的可靠解释叶，完整路径与输出不变。枚举不含冻结叶的最大子树根；每根始终保留原子树，分别尝试上下文深2和3的完整NN软概率熵划分，再添加计数的显式物理合法性判断。方向包括全部非恒定公开轴和按训练曝光选8个旧叶的最多80个稀疏logit差方向；每方向最多4个阈值，真实硬路由两边各至少160帧。

每个角色／折两个臂共享按深12的结构上限计算的node/leaf/proof调用预算，均搜索3600秒、总4200秒，3worker、BLAS单线程。深9有剩余深度不足时自然截断；未使用预算不转移。所有实际调用预扣账，失败也计数。最大新叶模型数为所有根和两个模板的2^min(12−根深,模板深+1)之和，按每模型72次leaf／320次proof计账；节点上限为对应完全二叉上下文节点数之和。

fit900内部80%整场景用于结构提议，内部20%选叶支持，全部fit900重拟合，cal150校准。仅使用已花费开发数据，不产生新环境轨迹。固定候选后沿用fit-only300/150/150和27/30场景子集可靠性、四个预登记全局权重、256总叶分配；外层资格／验证各300不进入参数或结构提议。

## 报告与决定

逐容量臂报告六项F/E覆盖、预期F、一致率、KL、非法／未证明数、内部可靠覆盖、实际深度和叶数、调用／时间，以及task分层。开发门槛仍F/E≥45%、预期F≥40%、一致≥95%／97%、KL≤0.20、非法／未证明0并且内部可靠门槛通过，六项逐项检查。

只有整个容量臂六项通过才能继续，若两个都通过优先深9；不拼接各臂或各角色的赢家。旧数据通过后仍需独立重放及全新一次性确认/压力数据，后续真实配对PPO、正式质量选择、一次性封存审计与留出、三域绑定及工程发布均保留。NN更新、PPO步数、程序训练梯度和新环境reset均0，pilot关闭。
