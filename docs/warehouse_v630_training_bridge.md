# v6.30 从独立确认到真实配对训练的衔接

## 本次发现与修复

旧v6.29训练程序通过完整路径相等寻找原受保护叶。v6.30允许在原路径下建立完整子分区，
这时旧函数不会把新子叶识别为受保护叶。直接复用旧重拟合器会尝试修改这些子叶，
随后在新程序的语义保护校验处失败；这不是当前后台抽取实验的结果问题。

新增`warehouse_v630_training_program.py`按原受保护路径的全部后代识别保护范围。
固定树、支持和合法witness；受保护子叶的系数、归一化和温度全部保持原样。
只对其余叶执行原固定支持拟合和重新认证的温度校准，每次求解仍预扣原账本。
四个训练证据分区按完整场景隔离，使用完整五动作掩码后NN目标。
所有叶均重新判资格，不能因为输出受保护而继承当前NN反馈资格。

这是纯数值原语，不提供训练授权、环境动作或NN权重更新；当前NN目标的来源与哈希仍须由实际owner证明。
程序内的Actor哈希继续表示不可变保护起点，当前NN目标哈希在外部证据封套另存，不能互相覆盖。

## 新准入

`v630_training_admission.py`与只读CLI要求：原18项全部完成且审计通过、同一方法六单元通过、
一次新确认和压力绝对门槛通过、主确认四个场景配对bootstrap端点通过；从绑定原数组重新评分。
仅有`confirmation.passed`布尔值不能授权训练。

参考缓冲仍读取原已审计v6.29准备包中的300个已花费argmax拟合场景，逐项复核完整来源，
不生成新缓冲，不将确认、资格或验证帧加入训练。训练程序固定取第0折双角色，禁止按分数改选。
全部输入、源快照、旧实验链和程序保护资产都纳入后续owner的哈希绑定。

准入通过本身也不创建环境或优化器。仍需要新版本有限20k配对owner、查重、单次claim、
当前NN证据provider、75/84/93%重拟合衔接、完整检查点与恢复后，才能启动真实配对训练。
本次未运行PPO、未更新NN，未使用新确认/压力或封存/留出场景，pilot保持关闭。
