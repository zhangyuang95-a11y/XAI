# Warehouse v6.27 执行登记

候选`warehouse-v627-semantic-compiled-01`。执行用户批准的语义树重建、合法性编译和真实资格评分方案。当前阶段只拟合冻结v6.20的完整掩码分布；任何Torch梯度均只更新外部程序候选，不更新Actor。

## 预算与方法

S32优先：语义树深5/16叶，编译后深6/32总叶；失败且六项算术复核完成才S64：语义树深6/32叶、编译后深7/64总叶。节点/叶各3公开源、线性叶20系数。每个移动终端追加对应legal_ACTION的显式分支，另一侧为独立计数、独立拟合和资格判定的后备叶（WAIT始终合法；其他动作仍须路径证明）。不能把fallback或空叶从分母/复杂度中删掉。

四起点：剥离旧证书后重编译的S1、完整NN分布贪心树、两个固定随机ExtraTree；全部重新证明。每起点必做全树梯度候选和根子树重建。14轮、beam宽4，允许探索暂时下降、最佳模型单独保存，不使用两轮停滞终止。梯度只提供候选；硬路由并完整重新拟合/校准/资格后的结果才用于选择。

fit内部按场景/task固定分成55%拟合、10%内部校准、15%内部资格、20%内部评分，四者不重叠。支持只在内部拟合上搜索，校准只选温度，资格用与最终相同的v622_eligible，评分按实际合格E覆盖、实际合格预期F覆盖、全分布KL、叶数排序。外部cal/elig/val不参与优化；最终固定结构和支持后全部外部fit重拟合。

每角色/折：叶求解20000、节点/整树求解1024、证明LP100000；整个作业内梯度步预扣总20000，每调用最多200，无退款。Adam .015、batch512、sigmoid导数温度.5，前向仍为存储raw-f32系数的共享fp64硬路由，每次投影3源且未选源可获梯度。搜索4800秒（留10秒结算）、最终600秒（预留8×总容量叶调用和52×容量证明调用）。所有四起点和beam共享预算，最多3个worker，BLAS/Torch单线程。

所有实际优化预扣、失败照计；内容寻址状态保存全部队列、cursor、beam、最佳模型、叶缓存及调用账本；显式安全暂停恢复等价；崩溃dirty拒绝恢复。候选回调内的Adam与RNG局部且按输入确定性重建，安全暂停只在完整候选边界。

## 硬门槛和后续

各角色/折F/E覆盖45%、预期F40%、F/E一致95/97%、KL≤.20、原始非法/未证明路径0；必须四起点必需探索完成。设计目标55/50%、98/99%、KL.10只是余量目标，不替代验收。全部六项通过首个容量即锁定方法，否则两容量失败关闭本候选。旧275局仅用于设计/开发，非独立泛化证明。

方法锁定才启动新275局（fit100含argmax50/cal25/elig75/val75）和72场景×3轨迹压力确认，场景先查重封存；C0与新方法同轨迹同预算。验证/压力均用严格开发门槛，两角色E与预期F的四个配对场景bootstrap单侧98.75%下界>0。失败后不在同一确认集调方法。

B通过后执行既定完整v6.20权重起点、全新critic/Adam/RNG、raw/reg配对PPO+真实停机cost+共同reference KL。仅reg获得资格有效且当前动作一致的外部反馈，raw零梯度。先20k校准对，再三新流重启200k/300k/400k，选全部三对通过的最小预算。程序75/84/93%提取，lambda80–85%升.01，每epoch重验；每流D≥5.5且≥.95同场景v620、C≤min(6,基线+1)、shutdown≤5%、严格程序门槛及reg双角色实际梯度。

正式三新配对仅按质量选择固定模型，再程序预审、一次独立封存审计及每task100新种子留出；正式门槛D5/C8/S10%、覆盖20%、一致85/90%、KL.35、非法/未证0，失败消费尝试，不重复使用封存集。

检查点开销≤10%是独立工程发布门槛，不阻止科学实验和报告；数值、预算、恢复是硬门槛。Warehouse科学通过后核验Pong/Kitchen既有收据、三域逐帧NN+物理掩码、policy_id/哈希、A/B同reg/C独立raw，全部通过才发布v6并开pilot。旧证据/实例只读；不引入执行动作规则。
