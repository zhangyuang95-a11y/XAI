# v6.42 条件20k配对训练入口

`scripts/run_warehouse_v642_calibration.py`衔接新有限owner、现场证据池、原生程序重拟合和当前NN反馈管理器。
三个阶段均先检查真实开发与一次新确认准入，之后才读取传入的训练计划：

1. `--prepare`：绑定并只读快照完整owner和controller源码；须在历史查重前完成。
2. `--audit-seeds`：四历史根的元数据、精确原参数与上下文查重，以及最终stat差异；绑定完整源码契约。
3. `--run`：单次claim下，raw/reg轮流收集、实际物理/NN重放与PPO，均完成20k联合步。

各命令同时要求`--reference-directory`和已封存`--plan`。
本CLI不自动分配新随机流、创建占位准入、重试、恢复或开放pilot。

每个版本在4k前只训练critic；重拟合固定于15k/16.8k/18.6k；程序λ保持80%–85%渐增到0.01。
raw程序梯度0，regularized逐次更新由新provider重验当前NN；验证失败锁存，直到下一次登记重拟合通过。
4k、15k、16.8k、18.6k和20k写入完整安全快照；快照不构成自动恢复许可。
source或clearance变化时拒绝继续。

完成训练只能写“校准训练结束”。任务保留、配送/碰撞/停机、程序覆盖/一致率/KL及工程性能仍需独立评估；
随后三个继续训练流的预算选择、正式阶段、一次封存/留出和三域发布均未由本完成标记替代。

测试使用临时fake准入与source snapshots核验顺序及拒绝路径，纯调度夹具不会启动训练。
v6.42深12开发六项及完整重放已通过，全新确认仍在进行；确认完成并通过前，CLI的真实训练准入仍关闭。

## 新语法与样本数

训练使用独立v6.42读者，显式保留maximum_depth=12和maximum_leaves=256。拟合时记录新的完整NN角色哈希，原始锚点哈希与保护路径/输出保持不变；每个后续epoch另绑定当前NN证据，不能沿用上一次更新的哈希。程序仅提供损失与证据，从不选择环境动作。

75%时每个版本收集全新1650个程序专用完整episode：fit900、calibration150、eligibility300、validation300，之后只在这些公开状态上为当前NN重新生成反事实分布并重验。数量在训练前锁定，四分区按场景分离且与NN梯度场景、旧开发、新确认及封存集隔离；两版本使用同一声明库存。实际训练40k联合步与程序证据物理步数分别记账，不能把后者隐去或当作训练质量评估。

数值检查已覆盖真实已锁定深11程序的固定支持重拟合、校准、资格和独立证书/路由；该检查只用旧开发数组，不是新模型训练结果。测试中的临时合成NN/模拟准入不构成科学训练许可。
